Hey! I'm building an internal Retrieval-Augmented Generation (RAG) pipeline for a customer support chatbot, and after two days of debugging I genuinely can't tell whether the issue is in my embeddings, chunking strategy, or vector database configuration.

The application is supposed to:

- ingest PDF manuals,
- split them into semantic chunks,
- generate embeddings,
- store them in Qdrant,
- retrieve the top-k chunks,
- and finally send them to an LLM.

The retrieval quality is surprisingly poor even though everything appears to work.

Here's the ingestion code.

from sentence_transformers import SentenceTransformer
from qdrant_client import QdrantClient

model = SentenceTransformer("all-MiniLM-L6-v2")
client = QdrantClient(host="localhost", port=6333)

embeddings = model.encode(chunks)

client.upsert(
    collection_name="manuals",
    points=[
        {
            "id": idx,
            "vector": emb.tolist(),
            "payload": {"text": chunk}
        }
        for idx, (emb, chunk) in enumerate(zip(embeddings, chunks))
    ]
)

The retrieval code looks like this.

query_embedding = model.encode(query).tolist()

results = client.search(
    collection_name="manuals",
    query_vector=query_embedding,
    limit=5
)

The documents are split using this function.

def split_text(text):

Configuration file

{
